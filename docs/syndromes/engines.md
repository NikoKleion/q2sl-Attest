# Engines

Eight routes compute the dependence of a code's syndrome on its encoded logical state. Each returns a
different quantity, and each is limited by a different cost.

| engine | returns | cost set by | reach |
|---|---|---|---|
| `core.Code`, `analyze.population_leak` | the leak, the total variation distance | 2^(n-k) projectors of size 2^n | about 11 qubits |
| `expectations.population_leak` | the leak | a state vector of 2^n entries | about 14 qubits |
| `analyze.analytic_leak` | the leak order | the Z-side span, 2^(Z generators + 1) elements | surface d=5, toric L=4, [[18,4,4]] |
| `zchecks.leak_order` | the leak order | an integer program | [[144,12,12]] in minutes |
| `tensor.l2_leak` | the L2 distance, and the leak from below | the width of a tensor network | surface d=11, 121 qubits |
| `sampled.leak_from_records`, `zchecks.leak_from_z` | the leak from below, through a statistic of sampled records | the number of shots | any size |
| `regions.z_region_leak` | the leak of chosen Z generators, and the leak from below | the codewords on the qubits those generators touch, times 2^(generators) | six generators of surface d=11, 22 qubits |
| `regions.css_region_leak` | the leak of chosen X and Z generators under relaxation, and the leak when every generator is chosen | 2^(generators) times the Z stabilizers and logicals on the touched qubits and off each X product | the whole record of surface d=5, 25 qubits |

## Exact simulation

`Code` builds every syndrome projector Pi_s and computes P(s | rho) = Tr(Pi_s E(rho)) on the full density
matrix. Memory sets its limit at about eleven qubits.

## Stabilizer expectations

```python
from syndrome_leakage import expectations as ex

sc = ex.surface_code_3()                                   # strings only, no projectors
leak, d0, d1 = ex.population_leak(sc, amplitude_damping(0.2))
e = ex.stabilizer_expectations(sc, amplitude_damping(0.2), t=0.0, phi=0.0)
d = ex.syndrome_dist(code, kraus, t, phi)
```

The syndrome projector expands over the stabilizer group:

    Pi_s = prod_j (I + (-1)^s_j g_j) / 2 = 2^-m sum_a (-1)^(s.a) S^a,    S^a = prod_j g_j^a_j
    P(s) = 2^-m sum_a (-1)^(s.a) <S^a>_E(rho)

(Kobori and Todo 2025, eq. 15; Blume-Kohout and Young 2025, eqs. 7 and 34). For a product channel and a
pure logical state, <S^a>_E(rho) = <psi| (x)_i E^dagger(P_i) |psi>. The cost is 2^m Pauli expectations on
an n-qubit state vector, with no 2^n by 2^n matrix. The syndrome order matches `Code.syndrome_dist`.

## Leak order by enumeration

```python
from syndrome_leakage.css import css_strings, code_distance
from syndrome_leakage.analyze import analytic_leak

sc = css_strings(Hx, Hz, "my code")
print(code_distance(Hx, Hz), analytic_leak(sc))
```

Under amplitude damping the two logical states' syndrome distributions first differ at the order
min |A| over supports A such that Z_A lies in the group generated by S and Z_L, A lies inside the Z-support
of some element of S, and A overlaps the support of X_L in an odd number of qubits. On a CSS code the
search runs over the Z-side span with its logical Z, 2^(Z generators + 1) elements, refused past
`max_group`, 2^20 by default. At the default it reaches the d=5 rotated surface code and refuses d=7, whose
span holds 2^25 elements.

## Leak order by integer programming

```python
from syndrome_leakage import zchecks
zchecks.leak_order(code)       # {"order", "a", "optimal", "dual_bound"}
zchecks.z_distance(code)       # the least weight of a nontrivial Z logical
```

The same order as the enumeration, as an integer program. The variables are a binary support a with
Hx a = 0, x_L . a = 1 for the active logical qubit and x_L' . a = 0 for the others, each modulo 2 through
an integer slack, and the objective is |a|. Containment in a Z stabilizer adds binary coefficients y, a
support h with Hz^T y - 2t - h = 0, and a <= h. The program is solved first without containment and its
optimum checked by a GF(2) solve; the larger program runs only when that check fails. `scipy.optimize.milp`
solves both with HiGHS. The result is the proven optimum, or the solver's lower bound in `dual_bound` when
`time_limit` stops it, and `None` for a protected code. `z_distance` minimises over all logical qubits.

## L2 distance

```python
from syndrome_leakage.analyze import l2_leak
l2, lower, upper, shape = l2_leak(code, amplitude_damping(0.05))

from syndrome_leakage import tensor
r = tensor.l2_leak(code, amplitude_damping(0.05))    # {"l2", "lower", "width"}
```

The leak is half the L1 distance between the two syndrome distributions. The L1 norm has an absolute value
inside the sum and does not factor, so no contraction computes it; the squared L2 norm does. By Parseval,

    ||d0 - d1||_2^2 = 2^-M sum_a (<g_a>_0 - <g_a>_1)^2

over the 2^M products g_a of the M generators. The leak is at least half the L2 distance.

`analyze.l2_leak` takes the L2 distance from the two exact distributions and returns the bounds it puts on
the leak, at least `l2 / 2` and at most `sqrt(effective support)` times that, with the shape factor
`||delta||_1 / ||delta||_2`, which is flat in the damping strength.

`tensor.l2_leak` contracts the sum. On a CSS code each expectation <g_a>_b is a sum over the logical
state's stabilizer group, whose elements are X^u Z^w, so every term is a product of one factor per qubit.
Three copies of the generator variables meet at each qubit: a for g_a, and b and c for the two factors of
the square. Each qubit carries a tensor built from t[u,w,x,z] = Tr(X^u Z^w E^dagger(X^x Z^z)), and parity
tensors join its local bits to the generator variables. The difference of the two logical states keeps
only the coset holding the active logical Z, so it is computed as one object. When the channel never
changes a Pauli's X part, as amplitude damping, dephasing, depolarizing, a coherent Z rotation and the
reset mixture do, the three copies share one set of X variables; each copy's sum then counts every allowed
pattern 2^(M_X - rank Hx) times, which the scale restores. The contraction times
2^-M 4^(1-M-k) 4^(M_X - rank Hx) is the squared L2 distance.

`width` is log2 of the largest intermediate tensor. The contraction refuses past `max_width`, 26 by
default, 2^26 complex entries. The plan comes from a seeded search of 64 random-greedy trials with subtree
reconfiguration (cotengra), so a given cotengra version returns the same plan on every run; a search of
your own can be passed as `optimize`. It needs cotengra, `pip install -e ".[tensor]"`, and reads CSS codes
only.

The exact engines compute the leak as a difference of two distributions and lose significance once those
agree to near machine precision. On the Hamming code the L2 distance over gamma cubed settles to a
constant:

| damping | exact engine | contraction |
|---|---|---|
| 1e-4 | 1.117687 | 1.117721 |
| 1e-5 | 1.252118 | 1.118003 |
| 1e-6 | 15.222137 | 1.118031 |
| 1e-10 | | 1.118034 |

The exact engines are reliable down to damping 1e-4, the value the `leak_order` run uses; a drifting shape
factor marks a result below that floor.

## Sampling under T1 and T2 relaxation

```python
from syndrome_leakage import sampled
p_reset, p_z = sampled.relaxation_mixture(60e-6, 163.3e-6, 77.0e-6)   # idle time, T1, T2
r0, r1 = sampled.sample_records(code, p_reset, p_z, shots=20000, seed=0)
sampled.leak_from_records(r0, r1, code, "z_weight")
```

Relaxation for a time t with T2 <= T1 is a mixture on each qubit: reset to |0> with probability
`1 - exp(-t/T1)`, and Z with probability `(1 - exp(-t (1/T2 - 1/T1))) / 2`. The populations match amplitude
damping; the reset leaves coherence at exp(-t/T1), and the Z mixture takes it to exp(-t/T2). Both
operations are Clifford, so a stabilizer simulator runs the channel on a code of any size. Qiskit Aer's
`thermal_relaxation_error` uses the same decomposition. `mixture_channel` gives the channel as Kraus
operators for the exact engines, and its Choi matrix equals that of `channel_from_t1t2` to 1e-14. Where
T2 > T1 the channel is not such a mixture and `relaxation_mixture` refuses.

`sample_records` returns the records of |0_L> and |1_L>, one row per shot and one column per generator,
with a 1 where the generator reads -1. The simulator is Stim. Every outcome Stim leaves undetermined is
drawn from numpy and forced (`peek_z`, `postselect_z`, `peek_observable_expectation`,
`postselect_observable`); an undetermined Pauli outcome on a stabilizer state is 50/50, so this is Born
sampling, and a seed fixes the records on any machine and Stim version. Any stabilizer code is read, with
parameters per qubit and optional readout error. It needs Stim, `pip install -e ".[stim]"`.

The records are compared through a statistic: `"syndrome"`, the full syndrome, for up to 24 generators;
`"weight"`, `"z_weight"` or `"x_weight"`; or a function of the records. The distance between the two
states' distributions of any statistic is at most the leak, so `leak_from_records` reads a lower bound, as
the plug-in distance with its permutation floor and as the distance an observer achieves on held-out shots.
A statistic that shows no difference does not bound the leak from above.

## The Z checks as a classical process

```python
from syndrome_leakage import zchecks
s0, s1 = zchecks.sample_syndromes(code, 0.3, 100000, seed=0)
c0, c1 = zchecks.sample_counts(code, 0.52, 10_000_000, "z_weight")
zchecks.leak_from_z(code, 0.52, 4_000_000, "z_weight")
```

The Z checks see only populations, and relaxation moves populations the same way at every T2, since
E^dagger(Z) = (1 - gamma) Z + gamma I for amplitude damping and for the reset mixture and dephasing leaves
Z unchanged. The Z-check syndrome therefore does not depend on T2.

It is a classical process. The Z-basis outcome of a CSS logical state |b_L> is uniform over x = c + b x_L
with c in the row span of Hx. A reset measures Z and applies X on outcome 1, so the resets on a set R leave
the X error E = x AND R, and the Z checks read Hz E. No quantum state is simulated. `exact_distribution`
enumerates the process for small codes; `sample_syndromes` draws it; `sample_counts` streams a statistic a
chunk at a time. `exact_z_distribution(code, p_reset, bit)` returns the exact distribution over the Z
syndromes from its characteristic function, a mean over the stabilizer codewords, at a cost of the number
of codewords times the number of Z syndromes, which reaches the distance 5 surface code.
`least_weight_x(code)` gives, for every Z syndrome, the least weight of an X error that has it.

Under this process x restricted to R is uniform on a coset of the restricted code, and the two logical
states' syndromes differ exactly when a Z stabilizer restricted to R is a Z logical of the active qubit.
The least such |R| is the order of the enumeration and of the integer program above.

The record of a chosen set of Z generators needs less. With U the qubits those generators touch, x
restricted to U is uniform over the row span of Hx restricted to U, shifted by x_L restricted to U, and
`regions.z_region_dist` takes the mean of the characteristic function over that span, whose size is set by
U and not by the code. With every Z generator chosen it returns `exact_z_distribution`.

`regions.css_region_dist` reaches the same record by the dual sum and takes X generators as well. The
expectation of a product of generators, X on B and Z on A, is the product of the coherence factors on B
times a sum over the Z stabilizers and Z logicals R that lie inside A and off B, each weighted by p on R and
1 - p on the rest of A outside B, with a sign for the logical. On sets of Z generators the two sums agree to
1e-15 on the distance 5 to 11 surface codes.

The statistics are `"z_weight"`, the number of Z checks that fire; `"parity"`, the parity of the decoded X
error against the active Z logical, from ldpc's BP+OSD or PyMatching; and `"parity_weight"`, the two
together. The X checks after a reset are random independently of x and the logical state, but not of R, so
the full record can carry more than the Z checks; every quantity here is a lower bound on the leak through
the Z checks. CSS codes whose logicals are of pure X and Z type are read.

## Reach by code

At the default limits, `max_group` of 2^20 for the order search and `max_width` of 26 for the
contraction. Every entry is measured. For a code with several logical qubits the order is that of logical 0.

| code | n | k | order search | contraction | integer program, order |
|---|---|---|---|---|---|
| Steane [[7,1,3]] | 7 | 1 | yes, protected | yes | protected |
| Shor [[9,1,3]], rotated surface d=3 | 9 | 1 | yes | yes | 3 |
| rotated surface d=5 | 25 | 1 | yes | yes | 5 |
| rotated surface d=7, d=9, d=11 | 49 to 121 | 1 | no | yes | 7, 9, 11 |
| rotated surface d=13 | 169 | 1 | no | no | 13 |
| hypergraph product of rep4 | 25 | 1 | yes | yes | 4 |
| hypergraph product of rep5 | 41 | 1 | no | yes | 5 |
| toric L=3 | 18 | 2 | yes | yes | 3 |
| toric L=4 | 32 | 2 | yes | no | 4 |
| bivariate bicycle [[18,4,4]] | 18 | 4 | yes | no | 4 |
| hypergraph product of Hamming [[58,16,3]] | 58 | 16 | no | no | 3 |
| bivariate bicycle [[72,12,6]] | 72 | 12 | no | no | 6 |
| bivariate bicycle [[144,12,12]] | 144 | 12 | no | no | 12 |

The order search is limited by the number of Z generators and the contraction by the width of the
network. A code with several logical qubits carries each other logical Z as a variable across its support
in two of the copies, and a periodic boundary adds to the width. The widths at the default search are 21
for surface d=11, 28 to 29 for d=13, 30 for toric L=4, 32 for [[18,4,4]], 75 for the Hamming hypergraph
product and 135 for [[72,12,6]].
